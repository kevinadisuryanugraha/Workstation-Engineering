# 6.1: Release & Deployment Recording API

**Story ID:** 6.1  
**Epic:** 6 — Release & Deployment Operations  
**Slug:** deployment-recording-api  
status: done   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->  

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **Tech Lead / DevOps Engineer / CI Runner**,  
I want **RESTful API endpoints to record deployments with target environment, server, commit SHA, and outcome status**,  
so that **deployment history is fully traceable, auditable, and linked to actual code releases**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Skema Drizzle `deployments` dan `deployment_logs` dibuat di PostgreSQL dengan field: `id`, `project_id`, `environment` (DEV, STAGING, PRODUCTION), `server_name`, `version`, `commit_sha`, `status` (PENDING, IN_PROGRESS, SUCCESS, FAILED, ROLLED_BACK), `deployed_by` (actor user ID atau system runner), `started_at`, `completed_at`, `created_at`.
2. Endpoint `POST /api/v1/deployments` (dilindungi `PERM_DEPLOYMENT_EXECUTE`) mencatat record deployment baru dengan validasi format commit SHA (40 karakter heksadesimal) dan environment.
3. Endpoint `GET /api/v1/deployments` mendukung filter per `projectId`, `environment`, dan status, mengembalikan daftar terurut secara kronologis mundur (*newest first*).
4. Catatan deployment secara otomatis menautkan record ke commit GitHub jika commit SHA ditemukan di tabel `commits`.
5. Setiap deployment berstatus `SUCCESS` atau `FAILED` di environment `PRODUCTION` memicu pencatatan audit log via `auditService.logEvent`.

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. -->

- **Approach:** Integration test lifecycle pencatatan deployment.
- **Key scenarios:**
  1. POST deployment dengan commit SHA tidak valid (misal "abc") ditolak validasi Zod (HTTP 400).
  2. POST deployment sukses mengembalikan HTTP 201 dengan ID deployment terdaftar.
  3. GET deployments menampilkan record terurut dari yang terbaru.
  4. Role `Viewer` ditolak HTTP 403 saat memanggil POST deployment.
