# 3.2: Client-Side Store Decomposition & REST Integration

**Story ID:** 3.2  
**Epic:** 3 — Developer Experience & "My Work" Workspace  
**Slug:** client-store-decomposition  
status: ready-for-dev  

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **Frontend Developer**,  
I want **the 13 `useState` hooks in `src/App.tsx` decomposed into modular Zustand global stores and React Query hooks that consume real REST APIs**,  
so that **the codebase is maintainable, re-renders are optimized, and views display real data instead of static mock files (fulfilling ADR-006)**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Dependensi `@tanstack/react-query` dan `zustand` terpasang di project.
2. Store global Zustand dibuat di `src/stores/`:
   - `useAppStore`: mengelola `activeTab`, `currentProjectId`, `isSearchOpen`, `isMobileNavOpen`.
   - `useAuthStore`: mengelola sesi login, user aktif, dan token, sinkron dengan `localStorage`.
3. Custom hooks React Query dibuat di `src/hooks/api/`:
   - `useWorkItems(projectId)`: fetch dan query invalidation untuk work items.
   - `useTickets(projectId)`: fetch dan query invalidation untuk tickets.
   - `useDeployments(projectId)`: fetch untuk deployments.
4. Ukuran file `src/App.tsx` direduksi dari 885 baris menjadi < 200 baris dengan memindahkan state management ke stores dan hooks tersebut.
5. Tampilan visual UI (Retro Desktop Shell, tema retro 90s, navigasi tab, dan PWA install button) tetap bekerja 100% identik tanpa perubahan gaya atau broken layout.
