# 20.2: Email Delivery — SMTP Terjadwal + Log report_deliveries

**Story ID:** 20.2
**Epic:** 20 — Scheduled Delivery: Cron, Email & WhatsApp (Course Correction 6)
**Slug:** email-delivery
status: ready-for-dev

## Story

As a **manajemen**,
I want **laporan berkala terkirim otomatis ke email penerima terdaftar**,
so that **pemangku kepentingan menerima laporan tanpa membuka aplikasi**.

## Acceptance Criteria

<!-- LOCKED -->

1. Setelah generate terjadwal sukses (20.1), `delivery.service.ts` mengirim ringkasan laporan via SMTP (`nodemailer`) ke daftar `REPORT_DELIVERY_EMAILS` (dipisah koma) — subjek `[{type}] Laporan WORKSTATION {periode}`, body HTML ringkas + lampiran PDF hasil export service 19.1.
2. Konfigurasi SMTP via env: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_SECURE` — bila tidak lengkap → **graceful skip** (log jujur + status SKIP di log delivery), TIDAK pernah crash boot atau job scheduler.
3. Tabel `report_deliveries` (BARU, append-only, migrasi Drizzle): `id, reportId, channel ('EMAIL'|'WHATSAPP'), destination, status ('SENT'|'FAILED'|'SKIPPED'), detail (text), createdAt` — setiap percobaan kirim tercatat; tidak ada update/delete.
4. Kegagalan SMTP → status FAILED + detail error ringkas; job scheduler tetap lanjut (konsisten AC4 20.1).
5. Audit-logged via `auditService` per delivery.
6. `npm run lint` + seluruh test hijau; test baru: skip tanpa config, SENT dengan SMTP palsu (inject transporter), FAILED tercatat, baris log delivery dibuat untuk setiap percobaan.

## Dev Notes

- **Deps baru:** `nodemailer` (+ `@types/nodemailer` dev).
- **Lampiran PDF:** gunakan `export.service.ts` dari 19.1 (fungsi render murni buffer) — jangan fetch HTTP ke diri sendiri.
- Transporter dibuat lewat factory agar test bisa inject transporter palsu (pola testability, bukan singleton kaku).
- Email penerima divalidasi format dasar; entri tidak valid di-skip dengan log, tidak menggagalkan batch.
- JANGAN menyimpan `SMTP_PASS` di log/audit — hanya host + penerima.
