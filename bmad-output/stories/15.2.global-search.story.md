# 15.2: Global Search API across Tickets / Work Items / KB / Incidents

**Story ID:** 15.2 · **Epic:** 15 · **Slug:** global-search
status: ready-for-dev

## Story

As a **Developer / Manager**, I want **one search box that finds anything — tickets, work items, KB articles, incidents**, so that **information is never lost in silos**.

## Acceptance Criteria

<!-- LOCKED -->
1. `GET /api/v1/search?q=<min 2 char>` (PERM_VIEW_DASHBOARD): mencari di tiket (key, title), work item (key, title), KB (title), insiden (code, title) — case-insensitive (ILIKE).
2. Hasil dikelompokkan per entityType dengan field: `entityType`, `key/code/slug`, `title`, `projectId`, `status`, `timestamp` (createdAt/detectedAt), dan `snippet` (bagian body/description yang cocok, maks 160 char).
3. `q` kurang dari 2 karakter → 400. Hasil dibatasi maks 10 per entitas, urut relevance sederhana (kecocokan key/code diutamakan).
4. Respons menyertakan `total` keseluruhan; tanpa hasil → array kosong per entitas (bukan error).

## Tasks / Subtasks
- [ ] Search service (4 query ILIKE + grouping) (AC #1, #2, #4)
- [ ] Route + validasi + mount (AC #3)
- [ ] Tests `tests/global-search.test.ts`

## Dev Notes
- FR-018 AC#2; Master PRD §19 ("Search results must indicate entity type, project, timestamp").
- ILIKE dengan parameter binding (hindari injection — jangan interpolasi string).
- RBAC satu permission read (PERM_VIEW_DASHBOARD) — semua entitas sudah read-safe per matriks.

## Testing
- Seed `q = "redis"` → menemukan insiden Redis + KB terkait; `q = "WRK-101"` → work item by key di urutan awal.
- `q = "a"` → 400; `q = "tidakadajudulaneh"` → semua kosong, total 0.
