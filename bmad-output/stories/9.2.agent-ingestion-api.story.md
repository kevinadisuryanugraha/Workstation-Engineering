# 9.2: Agent Telemetry Ingestion API & `server_metrics` Schema

**Story ID:** 9.2
**Epic:** 9 — Workstation Linux Server Agent
**Slug:** agent-ingestion-api
status: done   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **Platform Admin**,
I want **a authenticated ingestion endpoint that persists telemetry batches from workstation agents into PostgreSQL**,
so that **server health data becomes a queryable, permanent part of the platform's single source of truth**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Tabel `server_metrics` (id, serverName, cpuUsage, memoryTotal, memoryUsed, memoryFree, disks JSONB, recordedAt, createdAt) tersimpan di PostgreSQL via skema Drizzle + migrasi; terindex pada `(serverName, recordedAt DESC)`.
2. `POST /api/v1/agent/metrics` menerima **batch** sampel (array), memvalidasi shape (cpu 0-100, memory numeric ≥ 0, disks array), dan menyimpan seluruh batch secara atomik; batch invalid ditolak `HTTP 400` tanpa partial insert.
3. Endpoint di-autentikasi **token agen khusus** (`AGENT_INGEST_TOKEN` dari env, bandingkan constant-time) — berbeda dari JWT user; tanpa/mismatch token → `HTTP 401`.
4. Endpoint tidak ter-cover rate limiter login maupun RBAC user (jalur auth terpisah), tetap tercatat correlation ID.
5. Query internal `server/modules/server-metrics/**` menyediakan pembacaan: metrik terakhir per server + deret riwayat per rentang waktu (dipakai story 9.3).

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. -->

- **Approach:** Integration test end-to-end: token benar + batch valid → baris tersimpan; lalu baca via query service.
- **Key scenarios:**
  1. Batch 3 sampel valid → HTTP 201/200, 3 baris tercatat dengan recordedAt dari payload (bukan waktu server).
  2. Satu sampel invalid dalam batch → HTTP 400 dan 0 baris baru (atomik).
  3. Tanpa token / token salah → HTTP 401.
  4. `latest("kontabo-vps")` mengembalikan sampel dengan recordedAt terbaru.
