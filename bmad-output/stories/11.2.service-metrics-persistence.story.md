# 11.2: Service Metrics Persistence & Live Services Panel

**Story ID:** 11.2
**Epic:** 11 — Server Agent Service Monitoring
**Slug:** service-metrics-persistence
status: done

## Story

As a **Platform Admin**,
I want **service probe results persisted and surfaced on the server health cards**,
so that **the "Systemd Services Monitored by Agent" panel shows live status instead of placeholders**.

## Acceptance Criteria

<!-- LOCKED -->

1. Tabel `server_metrics` memiliki kolom `services` JSONB (nullable — kompatibel baris lama) via migrasi Drizzle.
2. Ingest API menerima field opsional `services[]` pada tiap sampel (`name`, `kind: http|tcp`, `target`, `healthy: boolean`, `latencyMs: number|null`, `checkedAt` ISO); sampel dengan shape services invalid ditolak 400.
3. Response `GET /api/v1/server-metrics` menyertakan `services` pada metrik terakhir tiap server.
4. Kartu Infrastructure menampilkan daftar layanan live: nama, badge Running/Warning/Stopped (healthy→Running; unhealthy→Stopped), target & latensi; server tanpa data services menampilkan state kosong rapi (bukan error).
5. Riwayat `history` juga mengembalikan kolom `services`.

## Tasks / Subtasks

- [ ] Skema & migrasi (AC: #1) — kolom `services` jsonb nullable + generate migrasi
- [ ] Ingest & baca (AC: #2, #3, #5) — validasi shape services, simpan, sertakan pada latest/history
- [ ] UI mapping (AC: #4) — `mergeServerTelemetry` memetakan `services` API → `ServerTelemetry.services` (status Running/Stopped)
- [ ] Tests — `tests/service-metrics.test.ts` (validasi shape, roundtrip persist via fake tx, mapping UI)

## Dev Notes

- **Requirements Citation:** Master PRD §30. [Source: docs/WORKSTATION_Super_Duper_PRD.pdf#30]
- **Kontrak UI:** `ServerTelemetry.services: { name, status: Running|Stopped|Warning, port?, memoryMb }[]` — mapping: healthy→Running (port dari target bila ada, memoryMb diisi 0 karena probe latency-based), unhealthy→Stopped. Panel sudah ada di `InfrastructureView.tsx` (baris "Systemd Services Monitored by Agent"). [Source: src/types.ts, src/components/InfrastructureView.tsx#240]
- **Backward compat:** `services` nullable; payload agent lama tanpa services tetap valid (nilai default `[]`). [Source: stories/9.2, stories/11.1]

## Testing

- **Key scenarios:**
  1. POST batch dengan services valid → tersimpan; latest mengembalikan services utuh.
  2. services dengan shape salah (healthy bukan boolean) → 400.
  3. Baris lama tanpa services → API mengembalikan `[]` (bukan null crash).
  4. Mapper UI: healthy→Running, unhealthy→Stopped.
