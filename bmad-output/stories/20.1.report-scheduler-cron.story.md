# 20.1: Report Scheduler Cron — Generate Otomatis Produksi

**Story ID:** 20.1
**Epic:** 20 — Scheduled Delivery: Cron, Email & WhatsApp (Course Correction 6)
**Slug:** report-scheduler-cron
status: ready-for-dev

## Story

As a **tim operasional**,
I want **laporan DAILY/WEEKLY/MONTHLY dibuat otomatis oleh server sesuai jadwal produksi**,
so that **arsip laporan selalu mutakhir tanpa bergantung pada seseorang mengklik tombol generate**.

## Acceptance Criteria

<!-- LOCKED -->

1. Modul `server/modules/reports/scheduler.service.ts` (BARU) menjalankan `node-cron` in-process: jadwal default via env `REPORT_CRON_DAILY` (default `0 7 * * *`), `REPORT_CRON_WEEKLY` (default `0 7 * * 1`), `REPORT_CRON_MONTHLY` (default `0 7 1 * *`) — zona waktu dari `REPORT_SCHEDULER_TZ` (default `Asia/Jakarta`).
2. Scheduler dikontrol flag `REPORT_SCHEDULER=on|off` (default **off** — boot produksi eksisting tidak berubah perilaku sampai diaktifkan eksplisit di env produksi).
3. Eksekusi generate idempoten: sebelum generate, cek `generated_reports` — bila arsip tipe terkait sudah ada dalam window periode yang sama (per tipe: hari yang sama / minggu ISO yang sama / bulan yang sama), skip dengan log; tidak pernah duplikat arsip.
4. Setiap eksekusi (sukses/skip/gagal) tercatat via `auditService` + log konsol terstruktur; kegagalan satu tipe TIDAK menghentikan tipe lain.
5. Scheduler dimulai/dihentikan dari bootstrap `server.ts` (setelah DB siap), dan mengekspor `startScheduler()`/`stopScheduler()` untuk test.
6. `npm run lint` + seluruh test hijau; test baru: idempotensi window, flag off = tidak menjadwalkan apa pun, gagal satu tipe tidak menghentikan lainnya (inject service palsu).

## Dev Notes

- **Deps baru:** `node-cron` (murni JS).
- **Idempotensi:** query `generatedReports` per tipe, bandingkan `generatedAt`/`periodTo` terakhir terhadap window kalender saat ini (hari/ISO-week/bulan lokal TZ).
- Panggil `generatedReportsService.generate(type, 'SCHEDULER')` — `generatedBy='SCHEDULER'` membedakan dari generate manual.
- Jangan blokir bootstrap: `startScheduler()` non-blocking; error ditangkap per-job.
- Pola env fail-safe: nilai cron tidak valid → log error + skip penjadwalan tipe itu (jangan crash boot).
