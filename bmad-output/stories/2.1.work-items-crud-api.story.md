# 2.1: Work Items Schema & CRUD API

**Story ID:** 2.1  
**Epic:** 2 — Work Items & Task Management  
**Slug:** work-items-crud-api  
status: ready-for-dev  

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **Developer / Project Manager**,  
I want **a robust RESTful CRUD API to create, view, filter, and update work items with auto-incremented keys (e.g. `WRK-101`) and priority/type schemas**,  
so that **engineering tasks are formally tracked in PostgreSQL with proper relation to projects and assignees**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Skema Drizzle `work_items` dibuat di PostgreSQL dengan field: `id`, `key` (unik), `project_id`, `title`, `description`, `type` (EPIC, FEATURE, TASK, SUBTASK, BUG, TECH_DEBT), `priority` (P0, P1, P2, P3), `status` (BACKLOG, READY, IN_PROGRESS, IN_REVIEW, READY_FOR_TEST, DONE, CANCELLED), `assignee_id`, `estimate_hours`, `created_at`, `updated_at`.
2. Saat work item baru dibuat via `POST /api/v1/work-items`, sistem meng-generate key otomatis berformat `{PROJECT_KEY}-{SEQUENCE}` (misal `WRK-101`).
3. Endpoint `GET /api/v1/work-items` mendukung filter dinamis berdasarkan `projectId`, `status`, `assigneeId`, dan pagination (`page`, `limit`), mengembalikan respons dengan standard envelope ADR-004.
4. Endpoint `PUT /api/v1/work-items/:id` mengizinkan update field judul, deskripsi, assignee, dan priority dengan validasi Zod.
5. Endpoint `DELETE /api/v1/work-items/:id` melakukan soft delete atau menghapus record jika berstatus `BACKLOG` (dilindungi `PERM_WORK_ITEM_DELETE`) dan mencatatnya ke audit log.

## Dev Notes

<!-- LOCKED. Concrete guidance compiled from planning docs with citations. -->

- **Requirements Citation:** FR-004 Work Item Lifecycle & Manajemen Tugas. [Source: prd.md#FR-004]
- **API Envelope:** Mengikuti format ADR-004 (`{ success: true, data: [...], meta: { page, total } }`). [Source: architecture.md#ADR-004]
- **Key Generation:** Format key adalah gabungan `project.key` + `-` + sequence integer. [Source: prd.md#FR-003]
- **Permissions:**
  - Create: `PERM_WORK_ITEM_CREATE`
  - Update: `PERM_WORK_ITEM_UPDATE`
  - Delete: `PERM_WORK_ITEM_DELETE`
  - Read: `PERM_VIEW_ENGINEERING` atau `PERM_VIEW_DASHBOARD`. [Source: architecture.md#ADR-003]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. -->

- **Approach:** Integration test memanggil API work items via Supertest.
- **Key scenarios:**
  1. POST work item menghasilkan key berurutan (`WRK-1`, `WRK-2`).
  2. GET dengan query filter `?status=IN_PROGRESS` hanya mengembalikan item yang cocok.
  3. Menghapus item tanpa hak `PERM_WORK_ITEM_DELETE` ditolak HTTP 403.
