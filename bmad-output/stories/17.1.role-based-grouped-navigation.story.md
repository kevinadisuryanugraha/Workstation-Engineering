# 17.1: Navigation Registry — Permission Filter + 3 Grouped Sections

**Story ID:** 17.1
**Epic:** 17 — UI Clarity & Role-Based Navigation (Course Correction 4)
**Slug:** role-based-grouped-navigation
status: ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **Developer (dan semua role lainnya)**,
I want **sidebar yang hanya menampilkan menu yang relevan untuk role saya, dikelompokkan dalam 3 seksi (Kerjaanku / Operations / Governance)**,
so that **saya tidak kewalahan oleh 15 menu yang tidak semuanya relevan (owner feedback: "padat & membingungkan") dan fokus saya ke pekerjaan harian terjaga**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Dibuat registry navigasi terpusat baru `src/config/navigation.ts` yang mendefinisikan seluruh item menu (15 item eksisting: overview, project360, workitems, tickets, incidents, git, deployments, infrastructure, ai, security, reports, report-id, blueprint, knowledge, audit) dengan dua atribut baru per item: `group` ("kerjaanku" | "operations" | "governance") dan `requiredPermission` (diambil dari `Permission` di `server/constants/permissions.ts` — lihat mapping di Dev Notes).
2. `Sidebar.tsx` merender menu HANYA dari registry `navigation.ts` (tidak ada lagi array nav hardcode seperti `opsNav`), dan memfilter item: item dengan `requiredPermission` yang TIDAK dimiliki role user saat ini disembunyikan sepenuhnya (tidak disabled, tidak terlihat).
3. Menu dikelompokkan menjadi 3 seksi berjudul yang dapat di-collapse/expand, dengan state collapse dipertahankan saat navigasi antar-view (persist di localStorage):
   - **Kerjaanku:** overview, project360, workitems, tickets
   - **Operations:** incidents, git, deployments, infrastructure, ai, reports, report-id, knowledge
   - **Governance:** security, audit
4. **Quick test owner:** user role `Developer` login dan hanya melihat grup "Kerjaanku" (plus item Operations yang permission-nya `PERM_VIEW_ENGINEERING` dimiliki Developer sesuai `SERVER_ROLE_PERMISSIONS`); user `Super Admin` melihat seluruh 15 item.
5. Logika filter diekstrak menjadi pure function (mis. `filterNavigation(items, permissions): NavItem[]`) yang tidak bergantung pada React, sehingga dapat diunit-test tanpa render.
6. Fitur collapse group MENGGUNAKAN `prefers-reduced-motion` (warstan fix audit H-2): tanpa animasi bila user memilih reduced motion.
7. Gaya visual tetap design system retro neo-brutalist eksisting (border 2px, hard shadow, grid paper); tidak ada perubahan palet warna.

## Dev Notes

- **Sumber masalah (CC-4):** `src/components/Sidebar.tsx` memuat 15 item nav rata TANPA satu pun referensi ke role/permission/PERM_* (hasil scan 19 Sep 2026, `bmad-output/project-documentation.md` §5/§7 Planning Note). Owner mengeluh UI padat; diagnosis meja party-mode: over-EXPOSURE, bukan over-engineering backend.
- **Sumber permission:** matriks role × permission ada di `server/constants/permissions.ts` (`SERVER_ROLE_PERMISSIONS`, 9 role) dan sudah dimirror di frontend `src/lib/rbac.ts`. GUNAKAN helper eksisting — jangan buat sistem permission kedua.
- **Mapping `requiredPermission` (titik awal, boleh disesuaikan saat dev dengan tetap konsisten dengan permissions.ts):** view data engineering → `PERM_VIEW_ENGINEERING`; view management (reports/report-id/project360) → `PERM_VIEW_MANAGEMENT`; security & audit → `PERM_VIEW_AUDIT` atau permission admin setara yang ada di permissions.ts; overview → `PERM_VIEW_DASHBOARD`. **Aturan kunci:** hanya gunakan permission yang SUDAH ADA di `server/constants/permissions.ts`; dilarang membuat permission baru di story ini.
- **Sejarah desain:** Master PRD menetapkan Developer sebagai pengguna pertama MVP (decision-log 18 Sep "User pertama: Developer") — filter ini mengembalikan UI ke prinsip tersebut tanpa menghapus fitur apa pun.
- **Terkait:** fix audit UI H-2 (reduced-motion) sudah live sejak commit `b432d23`; pertahankan pola yang sama (AC 6).
- **TIDAK dalam scope story ini:** menghapus view Blueprint (itu 17.3), mengubah sumber data (itu 17.2), perubahan RBAC server.
