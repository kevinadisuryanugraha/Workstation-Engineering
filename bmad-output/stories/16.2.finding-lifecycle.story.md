# 16.2: AI Finding Lifecycle State Machine + Audit

**Story ID:** 16.2 · **Epic:** 16 · **Slug:** finding-lifecycle
status: done

## Story

As a **Developer / Tech Lead**, I want **each AI finding tracked individually through a human-validated lifecycle**, so that **AI output becomes actionable work, not noise** (AI as analyst, not authority).

## Acceptance Criteria

<!-- LOCKED -->
1. Saat snapshot tersimpan, findings juga di-parse menjadi baris `ai_findings` individual (snapshotId FK, findingRef, title, category, severity, confidence, affectedFile, evidence, impact, suggestedRemediation, status default PENDING, detectedAt).
2. `GET /api/v1/ai/findings?snapshotRef=&status=&severity=` (PERM_AI_SCAN_TRIGGER) dengan filter + pagination ringan.
3. `PATCH /api/v1/ai/findings/:id/status` (PERM_AI_SCAN_TRIGGER) — state machine forward-only:
   PENDING → CONFIRMED | REJECTED | FALSE_POSITIVE;
   CONFIRMED → IN_PROGRESS | ACCEPTED_RISK | RESOLVED;
   IN_PROGRESS → RESOLVED | ACCEPTED_RISK.
   Transisi lain → 400 INVALID_TRANSITION. RESOLVED/REJECTED/FALSE_POSITIVE/ACCEPTED_RISK = terminal.
4. Setiap perubahan status tercatat ke audit trail (`AI_FINDING_STATUS_CHANGED`) dengan correlation ID.
5. Status lama tidak pernah ditimpa diam-diam: riwayat perubahan terlihat di audit.
