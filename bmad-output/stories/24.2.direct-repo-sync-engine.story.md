# 24.2: Direct Repository Sync Engine (Backend GitHub/GitLab On-Demand Fetcher)

**Story ID:** 24.2
**Epic:** 24 — Full Real CRUD Persistence & Direct Repository Sync (Course Correction 9)
**Slug:** direct-repo-sync-engine
status: ready-for-dev

## Story

As a **Developer / Tech Lead**,
I want **server dapat melakukan sinkronisasi langsung (on-demand pull) dari REST API publik/autentikasi GitHub dan GitLab dengan satu panggilan endpoint**,
so that **seluruh riwayat commit, author nyata, dan PR dapat langsung ditarik ke database WORKSTATION tanpa harus menunggu push webhook pasif**.

## Acceptance Criteria

<!-- LOCKED -->

1. Service BARU `server/modules/git/git-sync.service.ts`:
   - Menerima `repoId` (atau `provider` + `fullName` + `token?`).
   - Melakukan HTTP fetch ke provider REST API:
     - GitHub: `https://api.github.com/repos/{owner}/{repo}/commits?per_page=30` & `/pulls?state=all&per_page=20`.
     - GitLab: `https://gitlab.com/api/v4/projects/{encoded_path}/repository/commits?per_page=30` & `/merge_requests?per_page=20`.
     - Header `User-Agent: WORKSTATION-Engine` + `Authorization: Bearer/token <token>` bila token disediakan.
   - Mengubah commit dan PR dari remote provider menjadi format `NewCommit` dan `NewPullRequest`.
2. Integrasi ke `gitLinkerService`:
   - Setiap commit diproses via `gitLinkerService.processCommitAndLink` (simpan ke tabel `commits` + tautkan evidence ke `work_items` dan `tickets` via regex kode item).
   - Setiap PR diproses via `gitLinkerService.processPullRequestAndLink` (simpan ke tabel `pull_requests` + tautkan evidence).
3. Endpoint BARU:
   - `POST /api/v1/git/repositories/:id/sync` (requirePermission `PERM_EVIDENCE_ATTACH`): Sinkronkan repositori terdaftar berdasarkan ID.
   - `POST /api/v1/git/sync-url` (requirePermission `PERM_EVIDENCE_ATTACH`): Sinkronkan cepat berdasarkan URL repositori (misal `https://github.com/owner/repo`) + `projectId` (auto-register repo bila belum terdaftar, lalu jalankan sync).
   - Mengembalikan `{ success: true, data: { syncedCommits: number, syncedPRs: number, linkedKeys: string[] } }`.
4. Error handling & graceful fallback:
   - Jika repository privat dan tanpa token / API rate limit tercapai ➔ return 400/422 dengan pesan error jelas (`REPO_NOT_FOUND_OR_PRIVATE`, `RATE_LIMITED`).
5. Audit trail: Setiap sync on-demand mencatat log `REPOSITORY_SYNCED` via `auditService.logEvent`.
6. `npm run lint` + seluruh test hijau; test baru di `tests/git-sync-engine.test.ts` memverifikasi parser URL repositori, normalisasi commit/PR dari GitHub/GitLab, penanganan error 404/privat, dan proses linking evidence.
