# 9.1: Workstation Agent Metrics Daemon (CPU/RAM/Disk Collector)

**Story ID:** 9.1
**Epic:** 9 — Workstation Linux Server Agent
**Slug:** agent-metrics-daemon
status: ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **Tech Lead / Platform Admin**,
I want **a lightweight Linux daemon that periodically collects CPU, memory, and disk metrics from office servers and the Kontabo VPS**,
so that **server health is observable from WORKSTATION without manual SSH inspection**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Daemon (`agent/`) mengumpulkan metrik setiap `AGENT_INTERVAL_SECONDS` (default 60): persentase CPU, total/used/free memory, dan usage per filesystem (dipfilter ke filesystem nyata, bukan tmpfs/loop).
2. Identitas sumber dikonfigurasi via `AGENT_SERVER_NAME` (mis. `kantor-01`, `kontabo-vps`) dan dikirim pada setiap payload.
3. Daemon mengirim payload ke endpoint ingest dengan header `Authorization: Bearer <AGENT_TOKEN>`; bila server gagal dijangkau, sampel **di-buffer** (maks konfigurable, default 60 sampel) dan dikirim ulang (retry) saat koneksi pulih — data tidak hilang saat downtime singkat.
4. Daemon berjalan sebagai proses Node biasa (`npm run agent`) dan gagal-fast dengan pesan jelas bila env wajib (`AGENT_SERVER_URL`, `AGENT_TOKEN`, `AGENT_SERVER_NAME`) kosong.
5. Tidak menambah dependency berat — pengumpulan metrik memakai modul bawaan Node (`node:os`, eksekusi `df` bila perlu).

## Tasks / Subtasks

- [ ] Kolektor metrik (AC: #1)
  - [ ] `agent/collectors.ts` — CPU load (os.loadavg × 100/core), memori (os.totalmem/freemem), disk (parsing `df -kP`)
- [ ] Transport & buffer (AC: #2, #3)
  - [ ] `agent/transport.ts` — POST batch sampel + in-memory buffer + retry
- [ ] Bootstrap daemon (AC: #4)
  - [ ] `agent/index.ts` — env fail-fast, loop interval, graceful shutdown (SIGTERM)
  - [ ] Script `agent` di `package.json`
- [ ] Tulis Tests (AC: #1, #3, #4)
  - [ ] `tests/agent-daemon.test.ts` — format payload valid, buffer terkirim ulang setelah kegagalan, fail-fast env kosong

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. -->

- **Approach:** Unit test kolektor (shape & rentang nilai), unit test transport/buffer dengan fetch dimock, uji fail-fast env.
- **Key scenarios:**
  1. Payload sampel memuat `serverName`, `cpu`, `memory{total,used,free}`, `disks[]` dengan tipe benar.
  2. Saat POST gagal → sampel masuk buffer; saat POST sukses kembali → buffer terkirim dan dikosongkan.
  3. Env wajib kosong → proses exit dengan pesan error jelas (bukan crash diam).
