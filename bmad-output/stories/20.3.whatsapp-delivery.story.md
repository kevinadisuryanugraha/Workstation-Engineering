# 20.3: WhatsApp Delivery — Gateway HTTP Generik

**Story ID:** 20.3
**Epic:** 20 — Scheduled Delivery: Cron, Email & WhatsApp (Course Correction 6)
**Slug:** whatsapp-delivery
status: ready-for-dev

## Story

As a **manajemen**,
I want **ringkasan laporan berkala terkirim ke grup/kontak WhatsApp terdaftar**,
so that **laporan sampai ke kanal yang paling sering dibaca tim**.

## Acceptance Criteria

<!-- LOCKED -->

1. `delivery.service.ts` (dari 20.2) diperluas dengan channel WHATSAPP: POST HTTP ke provider gateway generik — `WA_GATEWAY_URL` + `WA_GATEWAY_TOKEN` (header `Authorization: Bearer`), body JSON `{ target, message }` (kompatibel pola Fonnte/Wablas).
2. Penerima dari `REPORT_DELIVERY_WA_NUMBERS` (dipisah koma, format internasional tanpa `+`); pesan = ringkasan teks polos laporan (heading + KPI utama) — TANPA lampiran file.
3. Gateway tidak dikonfigurasi → graceful SKIP (log jujur + status SKIP di `report_deliveries`), boot & scheduler tetap sehat.
4. Respons gateway non-2xx / timeout (10s) → status FAILED + detail ringkas; kegagalan TIDAK menghentikan channel email maupun tipe laporan lain.
5. Setiap percobaan tercatat di `report_deliveries` + audit log; nomor tidak valid di-skip per entri.
6. `npm run lint` + seluruh test hijau; test baru: skip tanpa config, SENT (fetch global dimock), FAILED non-2xx, pesan teks memuat judul & KPI utama.

## Dev Notes

- Gunakan `fetch` global Node 20+ — TIDAK perlu dependency baru.
- Timeout via `AbortController` (10 detik).
- Formatter teks: ambil dari `contentMarkdown` → strip sintaks markdown ringan (sama pola renderer 19.1), maks ±3500 karakter (aman untuk WA), potongan akhir "… (lampiran lengkap di WORKSTATION)".
- JANGAN log token gateway; destination boleh (nomor tujuan bukan secret).
