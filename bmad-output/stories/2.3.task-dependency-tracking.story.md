# 2.3: Task Dependency & Circular Blocker Prevention

**Story ID:** 2.3  
**Epic:** 2 — Work Items & Task Management  
**Slug:** task-dependency-tracking  
status: done   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->  

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **Tech Lead / Project Manager**,  
I want **to link dependencies between work items ("Blocked By" and "Blocks") with an automated circular dependency detection algorithm**,  
so that **bottlenecks are flagged early and tasks cannot deadlock each other**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Skema Drizzle `work_item_dependencies` dibuat di PostgreSQL dengan field: `id`, `blocked_work_item_id` (FK ke `work_items`), `blocker_work_item_id` (FK ke `work_items`), `created_at`, dengan unique constraint pada pasangan `(blocked_work_item_id, blocker_work_item_id)`.
2. Endpoint `POST /api/v1/work-items/:id/dependencies` menambahkan relasi blocker:
   - Request body: `{ "blockerId": "WRK-102" }` (menyatakan bahwa item `:id` diblokir oleh `WRK-102`).
3. Algoritma deteksi circular dependency (DFS / topological cycle check) dijalankan sebelum relasi disimpan:
   - Jika penambahan relasi tersebut akan menciptakan loop (contoh: A memblokir B, dan kini diminta B memblokir A), operasi DITOLAK dengan `HTTP 400 Bad Request` ("Circular dependency detected: WRK-101 -> WRK-102 -> WRK-101").
4. Endpoint `DELETE /api/v1/work-items/:id/dependencies/:dependencyId` menghapus relasi blocker.
5. Pada respons detail work item, field `blockers` (tugas yang memblokir item ini) dan `blocking` (tugas yang diblokir oleh item ini) ditampilkan beserta statusnya. Jika ada blocker yang belum `DONE`, item ditandai secara visual di antarmuka.

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. -->

- **Approach:** Unit testing algoritma graf dan integration testing endpoint dependency.
- **Key scenarios:**
  1. Relasi A diblokir oleh B berhasil dibuat (HTTP 201).
  2. Menambahkan relasi B diblokir oleh A menghasilkan error circular dependency (HTTP 400).
  3. Menambahkan relasi multi-hop: A diblokir B, B diblokir C, dan C diminta diblokir A menghasilkan error circular dependency (HTTP 400).
