# 8.1: HTTP Hardening Middleware (Rate Limit, Helmet, Body Limit)

**Story ID:** 8.1
**Epic:** 8 — Security Hardening & Token Governance
**Slug:** http-hardening-middleware
status: done   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **Platform / Security Admin**,
I want **login endpoint rate limiting, standard security headers, and a tightened request body limit applied at the HTTP layer**,
so that **brute-force attacks, browser-based attacks, and memory-exhaustion DoS are mitigated before reaching application logic**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Endpoint `POST /api/v1/auth/login` dibatasi maksimal **5 permintaan per 15 menit per alamat IP**; permintaan ke-6 menerima `HTTP 429 Too Many Requests` dengan pesan yang jelas.
2. Seluruh response HTTP server menyertakan security headers standar (`Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `X-Frame-Options`) dan **tidak lagi** menyertakan header `X-Powered-By`.
3. Batas ukuran body JSON global diturunkan dari `10mb` menjadi `500kb`; request dengan body melebihi batas ditolak dengan `HTTP 413 Payload Too Large`.
4. Seluruh endpoint lain (non-login) tetap berfungsi normal setelah pemasangan middleware (regresi: 49 test lama tetap lulus).
5. Konfigurasi rate limit didefinisikan terpusat dan dapat di-tune via environment variable tanpa mengubah kode rute.

## Tasks / Subtasks

<!-- Every task maps to one or more ACs via (AC: #N). -->

- [ ] Pasang dependency hardening (AC: #1, #2)
  - [ ] `npm install helmet express-rate-limit`
- [ ] Pasang middleware keamanan di server bootstrap (AC: #2, #3)
  - [ ] `app.disable("x-powered-by")` + `app.use(helmet())` sebelum route
  - [ ] Ubah `express.json({ limit: "500kb" })`
- [ ] Buat rate limiter khusus auth (AC: #1, #5)
  - [ ] `server/middlewares/rateLimit.ts` — konfigurasi window/limit dari `env`
  - [ ] Terapkan hanya pada `/api/v1/auth/login`
- [ ] Tulis Integration Tests (AC: #1, #2, #3, #4)
  - [ ] `tests/http-hardening.test.ts` — 429 setelah limit, header keamanan ada, `X-Powered-By` hilang, body >500kb ditolak 413

## Dev Notes

<!-- LOCKED. Concrete guidance compiled from planning docs with citations. -->

- **Requirements Citation:** SEC-02, SEC-03, SEC-04. [Source: docs/DEEP-SCAN-REPORT-2026-09-18.md §5]
- **Server bootstrap:** Seluruh middleware terpasang di `server.ts` (bootstrap Express). Helmet harus dipasang **sebelum** definisi rute agar semua response ter-cover. [Source: architecture.md#ADR-001]
- **Rate limit scope:** Hanya endpoint login, bukan global — hindari mengunci workflow webhook GitHub (`/api/webhooks/github`) yang menerima burst dari GitHub. [Source: stories/5.1.github-webhook-receiver.story.md]
- **Env tunable:** Gunakan pola fail-fast yang sama dengan `server/config/auth.ts` untuk membaca `RATE_LIMIT_WINDOW_MINUTES` / `RATE_LIMIT_MAX` (beri default aman 15/5). [Source: stories/1.3.secure-auth-engine.story.md]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. -->

- **Approach:** Integration testing langsung terhadap app Express (pola `supertest`-style yang dipakai test suite existing).
- **Key scenarios:**
  1. 6x POST login berturut-turut dari IP sama → permintaan ke-6 HTTP 429.
  2. `GET` endpoint publik/sehat → response memuat `x-content-type-options: nosniff` dan tanpa `x-powered-by`.
  3. POST dengan body JSON > 500kb → HTTP 413.
  4. Suite test existing (49 test) tetap lulus penuh.
