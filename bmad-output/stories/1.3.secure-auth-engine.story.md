# 1.3: Hardened Authentication Engine (bcrypt + Stateless JWT)

**Story ID:** 1.3  
**Epic:** 1 — Core Platform Foundation, Security & Database  
**Slug:** secure-auth-engine  
status: done   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->  

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **Security Admin / User**,  
I want **a cryptographically hardened authentication engine with bcrypt password hashing (cost factor 12) and stateless JWT verification that fails fast without hardcoded secrets**,  
so that **passwords cannot be recovered from leaks and unauthorized attackers cannot bypass authentication (closing Deep Scan DS-01, DS-04, DS-06, DS-08)**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Password di-hash menggunakan library teruji (`bcryptjs`) dengan cost factor minimal 12, menggantikan SHA-256 tanpa salt yang ada saat ini.
2. Endpoint `POST /api/v1/auth/login` memvalidasi email dan password terhadap tabel `users` di PostgreSQL:
   - Mengembalikan token JWT HMAC-SHA256 valid dengan expiry 24 jam dan data user jika kredensial cocok.
   - Mengembalikan HTTP 401 Unauthorized dengan pesan kesalahan generik jika email tidak ditemukan atau password salah.
3. Seluruh pengecualian hardcoded backdoor (seperti `password === "admin123"`) dihapus total dari kode server.
4. Nilai `JWT_SECRET` wajib dibaca dari environment variable (panjang minimal 32 karakter). Jika `JWT_SECRET` tidak disetel atau berupa nilai default tiruan, server wajib gagal start (*fail-fast*) dengan pesan kesalahan jelas saat boot.
5. Endpoint `GET /api/v1/auth/me` memverifikasi Bearer token via `authenticateToken` middleware dan mengembalikan identitas sesi user yang terotentikasi.
6. Permintaan ke API tanpa menyertakan Bearer token valid wajib ditolak dengan HTTP 401 Unauthorized (menghapus fallback auto-admin default).

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. -->

- **Approach:** Unit testing fungsi kriptografi dan integration testing endpoint login & me.
- **Key scenarios:**
  1. `hashPassword("secret")` menghasilkan string hash valid yang cocok saat di-compare via `comparePassword`.
  2. Request `POST /api/v1/auth/login` dengan password salah mengembalikan HTTP 401.
  3. Request `POST /api/v1/auth/login` dengan password "admin123" pada akun non-default ditolak (memverifikasi backdoor telah musnah).
  4. Request `GET /api/v1/auth/me` tanpa header Authorization mengembalikan HTTP 401.
  5. Server melempar fatal error saat di-boot jika `JWT_SECRET` tidak ada di environment.
