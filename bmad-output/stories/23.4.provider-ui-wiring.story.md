# 23.4: Multi-Provider Git — UI Wiring (Badge Provider, Registry Form, Hydration)

**Story ID:** 23.4
**Epic:** 23 — Multi-Provider Git (Course Correction 8, Master PRD §30 Fase V2)
**Slug:** provider-ui-wiring
status: done

## Story

As a **Tech Lead**,
I want **melihat badge provider (GitHub/GitLab/Bitbucket) pada feed commit & MR/PR, serta bisa mendaftarkan repo provider mana pun langsung dari UI tanpa insert database manual**,
so that **panel Git mencerminkan realitas multi-provider tim dan onboarding repo baru tidak lagi membutuhkan akses DB**.

## Acceptance Criteria

<!-- LOCKED -->

1. `src/types.ts` (DTO mirror): tipe `GitProvider = 'GITHUB' | 'GITLAB' | 'BITBUCKET'`, `GitRepositoryDto` (id, projectId, fullName, provider, defaultBranch, hasSecret, createdAt), field `provider?: GitProvider` pada DTO commit & PR. Mapper eksplisit di `src/lib/contractMappers.ts` (`mapGitRepositoryDto`) — pola wajib mapper 18.x/22.1.
2. Hook BARU `src/hooks/api/useGitRepositories.ts`: `useGitRepositories(projectId?)` (list) + `useRegisterRepository()` (mutation POST, invalidasi cache React Query, pesan error jujur dari envelope). Gate write: hanya render aksi registrasi untuk role dengan `PERM_EVIDENCE_ATTACH` (mirror client `src/lib/rbac.ts` — verifikasi helper eksisting; jangan duplikasi).
3. Form registrasi repo di panel Git: pilih provider (3 pilihan), input `owner/repo`, pilih project, default branch opsional; setelah sukses tampilkan URL webhook yang harus dipasang di provider (`/api/v1/webhooks/{github|gitlab|bitbucket}`) + catatan cara pasang secret (GitLab: Deploy key/Webhook token; Bitbucket/GitHub: secret HMAC) — teks bantuan jujur, tanpa klaim otomatis.
4. Badge provider pada feed commit & MR/PR (komponen Git eksisting di App.tsx): badge teks kecil `[GitHub]` / `[GitLab]` / `[Bitbucket]` per item, sumber data `provider` dari read API 23.3; item tanpa provider (data legacy) tanpa badge — jujur, bukan default palsu.
5. Mode demo (`VITE_DEMO_MODE`) tetap menampilkan mock legacy dengan label demo eksisting — tidak ada data palsu di jalur real. Honest loading/error/empty untuk list repositori & registrasi (pola CC-4/17.2).
6. `npm run lint` + seluruh test hijau; test baru di `tests/git-provider-ui.test.ts`: mapper repository DTO (field asing dibuang, secret tidak pernah ada di tipe), gate permission aksi registrasi, badge provider per provider + tanpa badge bila undefined, form validasi (fullName tanpa `/` ditolak), state honest error 4xx/5xx.

## Dev Notes

- **Menjaga kemenangan CC-4:** TIDAK ada menu/nav baru — semua hidup di panel Git eksisting (App.tsx blok Git). Kepadatan UI dijaga: form registrasi di-balik tombol ("Tambah Repositori"), bukan selalu-tampil.
- Secret webhook TIDAK PERNAH sampai ke client (kontrak 23.1) — form hanya mengirim metadata; teks bantuan mengarahkan admin melihat secret di penyimpanan server (env/DB) sesuai praktik 23.1.
- Pola hydration & mapper: ikuti `useGitEntities.ts` + `contractMappers.ts` eksisting (18.1) — jangan membuat jalur data paralel.
- React Query invalidation: register sukses → invalidate `['git','repositories']` (dan list commit/PR bila terpengaruh).
- Badge = teks ringan (bukan ikon baru) agar konsisten dengan bahasa visual CC-4.
