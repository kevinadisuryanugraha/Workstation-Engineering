# 11.1: Agent Service Probes (Nginx HTTP, MySQL & Redis TCP)

**Story ID:** 11.1
**Epic:** 11 — Server Agent Service Monitoring
**Slug:** agent-service-probes
status: done

## Story

As a **Platform Admin / Tech Lead**,
I want **the agent to probe critical services (Nginx, MySQL, Redis) on each server**,
so that **service outages are detected at the source, not just hardware pressure**.

## Acceptance Criteria

<!-- LOCKED -->

1. Daemon memeriksa layanan yang dikonfigurasi via `AGENT_SERVICES` (format: `name:type:host:port`, dipisah `;`, contoh: `nginx:http:127.0.0.1:80;mysql:tcp:127.0.0.1:3306;redis:tcp:127.0.0.1:6379`); default jika env kosong: ketiga layanan di localhost dengan port standar.
2. Probe `http` dianggap SEHAT bila HTTP status < 500 (redirect/401 tetap sehat — service hidup); probe `tcp` SEHAT bila koneksi TCP berhasil dibuka dan ditutup bersih.
3. Hasil probe berupa array `services: [{ name, kind, target, healthy, latencyMs, checkedAt }]` yang ditambahkan ke payload sampel agent.
4. Kegagalan probe (timeout/refused) TIDAK membuat daemon crash — tercatat `healthy: false` dengan latency null dan daemon lanjut berjalan.
5. Timeout probe per layanan dapat dikonfigurasi (`AGENT_PROBE_TIMEOUT_MS`, default 3000).

## Tasks / Subtasks

- [ ] Probe engine (AC: #1, #2, #5)
  - [ ] `agent/collectors.ts` — `probeServices(config)`: parser config + probe http/tcp via `node:http` & `node:net`
- [ ] Integrasi loop (AC: #3, #4)
  - [ ] `collectSample` menyertakan `services` pada payload

## Testing

- **Key scenarios:**
  1. `AGENT_SERVICES` invalid format → fail-fast dengan pesan jelas.
  2. TCP probe ke server nyata (ephemeral listener) → healthy + latency terukur.
  3. TCP probe ke port mati → healthy:false, daemon tidak throw.
  4. HTTP probe ke server yang membalas 404/200 → healthy:true.
