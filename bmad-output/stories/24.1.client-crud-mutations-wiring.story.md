# 24.1: Client CRUD Mutations Wiring — Work Items & Tickets Persisted to REST API

**Story ID:** 24.1
**Epic:** 24 — Full Real CRUD Persistence & Direct Repository Sync (Course Correction 9)
**Slug:** client-crud-mutations-wiring
status: ready-for-dev

## Story

As a **Developer / Tech Lead**,
I want **setiap pembuatan dan pembaruan status Work Item dan Tiket di UI langsung tersimpan permanen ke endpoint REST API backend (`/api/v1/work-items` dan `/api/v1/tickets`) dan database PostgreSQL**,
so that **seluruh perubahan status dan data yang saya masukkan tidak hilang saat halaman dimuat ulang (bukan sekadar in-memory state lokal)**.

## Acceptance Criteria

<!-- LOCKED -->

1. `handleCreateWorkItem` di `src/App.tsx` mengirim `POST /api/v1/work-items` dengan payload `{ projectId, title, type, priority, description, estimateHours }`. Data baru langsung di-persist ke PostgreSQL dan query cache `workItems` di-invalidate via React Query.
2. `handleUpdateWorkItemStatus` di `src/App.tsx` mengirim `PUT /api/v1/work-items/:id` dengan `{ status: newStatus }`. Respons server memperbarui item di state dan database PostgreSQL. Bila API gagal, UI mengembalikan status ke nilai semula (*optimistic rollback*) dan menampilkan notifikasi kesalahan.
3. `handleCreateTicket` di `src/App.tsx` mengirim `POST /api/v1/tickets` dengan payload `{ projectId, title, type, severity, priority, description }`. Data tersimpan ke tabel `tickets` di PostgreSQL dan query cache `tickets` di-invalidate.
4. `handleUpdateTicketStatus` di `src/App.tsx` memanggil endpoint backend yang sesuai (`POST /api/v1/tickets/:id/resolve` jika status `RESOLVED`/`CLOSED` atau update status tiket) sehingga perubahan status tiket persisten di PostgreSQL.
5. Mode demo (`VITE_DEMO_MODE`) tetap bekerja secara in-memory mock tanpa mengirim request mutasi ke API — menjaga integritas mode demo.
6. `npm run lint` + seluruh test hijau; test baru di `tests/client-crud-wiring.test.ts` memverifikasi mapper mutasi, request payload yang dikirim, penanganan error, dan integrasi API mutasi.

## Tasks / Subtasks

- [ ] Task 1: Buat hook mutasi `useWorkItemMutations` & `useTicketMutations` (atau perluas hook eksisting) dengan `useMutation` React Query
- [ ] Task 2: Hubungkan `handleCreateWorkItem` & `handleUpdateWorkItemStatus` di `src/App.tsx` ke mutasi REST API
- [ ] Task 3: Hubungkan `handleCreateTicket` & `handleUpdateTicketStatus` di `src/App.tsx` ke mutasi REST API
- [ ] Task 4: Tulis test `tests/client-crud-wiring.test.ts`
- [ ] Task 5: Verifikasi lint + test suite + build

## Dev Notes

- Backend `server/modules/work-items/work-item.routes.ts` (`POST /`, `PUT /:id`, `DELETE /:id`) dan `server/modules/tickets/ticket.routes.ts` (`POST /`, `POST /:id/resolve`) sudah siap dan teruji.
- Pastikan payload DTO yang dikirim dari UI sesuai dengan Zod schema di server: `createWorkItemSchema`, `updateWorkItemSchema`, `createTicketSchema`.
- Gunakan `apiRequest` dari `src/lib/apiClient.ts` yang otomatis menyertakan header `Authorization: Bearer <token>`.
