# 4.3: Ticket Comments & Chronological Activity Timeline

**Story ID:** 4.3  
**Epic:** 4 — Ticketing & ITSM Issue Resolution  
**Slug:** ticket-comments-timeline  
status: ready-for-dev  

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **Developer / QA / Support Specialist**,  
I want **to post markdown comments on tickets and view a unified chronological timeline of comments and status transitions**,  
so that **the conversation history and state changes behind an issue are visible to all team members**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Skema Drizzle `ticket_comments` dibuat di PostgreSQL dengan field: `id`, `ticket_id` (FK ke `tickets`), `author_id` (FK ke `users`), `content` (teks markdown), `created_at`, `updated_at`.
2. Skema Drizzle `ticket_history` dibuat di PostgreSQL untuk mencatat audit internal tiket: `id`, `ticket_id`, `actor_id`, `field_changed`, `old_value`, `new_value`, `created_at`.
3. Endpoint `POST /api/v1/tickets/:id/comments` menambahkan komentar baru (dilindungi `PERM_TICKET_UPDATE`).
4. Endpoint `GET /api/v1/tickets/:id/timeline` mengembalikan feed terpadu gabungan antara komentar dan record riwayat perubahan status, diurutkan secara kronologis maju (`created_at ASC`).
5. Setiap kali status, severity, priority, atau assignee tiket berubah, sistem secara otomatis memasukkan record riwayat ke tabel `ticket_history`.

## Dev Notes

<!-- LOCKED. Concrete guidance compiled from planning docs with citations. -->

- **Requirements Citation:** FR-009 Komentar, Lampiran, dan Timeline Tiket. [Source: prd.md#FR-009]
- **Chronological Timeline:** Feed timeline bersifat append-only. Komentar tidak boleh diubah oleh user lain selain author aslinya. [Source: docs/WORKSTATION_Super_Duper_PRD.pdf#Section-6.3]
- **Markdown Support:** Konten disimpan sebagai string markdown mentah; rendering dilakukan di sisi klien dengan perlindungan escaping default React. [Source: architecture.md#ADR-004]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. -->

- **Approach:** Integration testing penambahan komentar dan agregasi timeline.
- **Key scenarios:**
  1. POST komentar pada tiket mengembalikan HTTP 201 dengan author terhubung.
  2. Mengubah status tiket otomatis menghasilkan event di `ticket_history`.
  3. GET timeline mengembalikan komentar dan perubahan status dalam urutan waktu yang tepat.
