# 6.2: Rollback Authorization Operations & Tamper-Evident Audit

**Story ID:** 6.2  
**Epic:** 6 — Release & Deployment Operations  
**Slug:** rollback-authorization-ops  
status: done   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->  

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **Tech Lead / System Admin**,  
I want **an authorized rollback operation endpoint (`POST /api/v1/deployments/rollback`) that strictly enforces `PERM_DEPLOYMENT_ROLLBACK`, mandates a rollback reason, and generates a tamper-evident audit signature**,  
so that **emergency recovery is recorded safely without allowing unauthorized junior roles to roll back production systems**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Endpoint `POST /api/v1/deployments/rollback` mewajibkan permission `PERM_DEPLOYMENT_ROLLBACK` (hanya Tech Lead, Org Admin, dan Super Admin yang diizinkan; Developer dan role lain ditolak `HTTP 403 Forbidden`).
2. Request body divalidasi via Zod:
   - `deploymentId` (string, wajib)
   - `targetVersion` (string, wajib)
   - `reason` (string, minimal 10 karakter penjelasan alasan rollback)
3. Sistem membuat record baru di tabel `deployments` dengan status `ROLLED_BACK`, mereferensikan deployment asal dan versi target.
4. Sistem menghasilkan tanda tangan audit kriptografis HMAC-SHA256 (`cryptographicSignature`) yang ditandatangani dengan server secret dan disimpan di audit log bersama alasan rollback.
5. Respons endpoint mengembalikan data otorisasi rollback lengkap beserta timestamp audit dan identitas Tech Lead/Admin yang mengesahkan.

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. -->

- **Approach:** Integration test otorisasi RBAC dan integritas record.
- **Key scenarios:**
  1. Pengguna dengan role `Developer` ditolak HTTP 403 Forbidden saat memanggil rollback.
  2. Pengguna dengan role `Tech Lead` berhasil memanggil rollback jika mengisi alasan lengkap (HTTP 200).
  3. Pemanggilan rollback dengan alasan kurang dari 10 karakter ditolak HTTP 400 Bad Request.
  4. Record audit log terbukti terbentuk di database menyertakan signature dan reason.
