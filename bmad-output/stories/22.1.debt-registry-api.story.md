# 22.1: Debt Registry — Skema & API (origin, evidence, impact, aging)

**Story ID:** 22.1
**Epic:** 22 — Technical Debt Registry (Course Correction 7 / DEF-006, Master PRD §11.4)
**Slug:** debt-registry-api
status: ready-for-dev

## Story

As a **tech lead**,
I want **setiap debt item memiliki origin, evidence, impact, effort, owner, target milestone, status, dan aging yang terstruktur dan dapat di-query via satu endpoint registry**,
so that **hutang teknis terlacak sistematis — bukan hanya teks bebas di deskripsi work item**.

## Acceptance Criteria

<!-- LOCKED -->

1. Migration `0016_add_debt_fields.sql` (BARU): tabel `work_items` ditambah 3 kolom nullable — `debt_origin` varchar(30), `debt_impact` varchar(10), `debt_source_ref` varchar(120) — tanpa breaking change ke endpoint/endpoint payload eksisting. Kolom hanya bermakna saat `type = 'TECH_DEBT'` (server-authoritative: create/update dengan type selain TECH_DEBT mengabaikan/men-null-kan field debt).
2. Zod schema create/update (`work-item.schema.ts`) menerima field opsional `debtOrigin` (enum: `AI_SCAN | TECH_LEAD_AUDIT | CODE_REVIEW | MANUAL | INCIDENT`), `debtImpact` (enum: `HIGH | MEDIUM | LOW`), `debtSourceRef` (string, maks 120) — divalidasi ketat, nilai di luar enum ditolak 400.
3. Endpoint BARU `GET /api/v1/work-items/debts` (requirePermission `PERM_WORK_ITEM_VIEW`): mengembalikan seluruh work item `type = 'TECH_DEBT'` dalam envelope standar `{ success, data, error, meta }` dengan per item: field work item relevan (key, title, status, priority, assignee/owner, milestone/target, estimateHours, createdAt, debtOrigin, debtImpact, debtSourceRef) + `agingDays` terkomputasi (floor selisih UTC dari `created_at`) + `agingBucket` (`FRESH` 0–30, `AGING` 31–90, `STALE` 91–180, `CRITICAL` >180) + evidence terstruktur bila tersedia. Query filter didukung: `?projectId`, `?status`, `?origin`, `?impact`. `meta.summary` berisi agregat: `{ total, open, byStatus, byOrigin, byImpact, byAgingBucket }`.
4. Endpoint konversi rekomendasi AI eksisting (`POST /api/v1/ai/recommendations/:id/convert`) kini mengisi field terstruktur: `debt_origin = 'AI_SCAN'`, `debt_impact` hasil mapping heuristik dari `expectedImpact` (mengandung "high"/"tinggi" → HIGH; "low"/"rendah" → LOW; selain itu MEDIUM), `debt_source_ref` = `` `${scanRef}/${recRef}` `` — approval manusia & idempotensi 16.3 TIDAK berubah (bukti: description evidence tetap ditulis).
5. DTO mirror di `src/types.ts`: field opsional debt* pada tipe WorkItem + tipe `DebtRegistryItem`/`DebtRegistrySummary`; `mapWorkItemDto` (`src/lib/contractMappers.ts`) memetakan field baru bila ada. Interface legacy `TechnicalDebt` TIDAK dihapus di story ini (dipakai demo mode).
6. `npm run lint` + seluruh test hijau; test baru di `tests/debt-registry.test.ts`: migrasi kolom (up), validasi enum, endpoint registry (aging math deterministik — clock di-inject/fixed, bucket benar di tiap batas 30/90/180, filter, agregat, 403 tanpa permission), konversi AI mengisi ketiga field, regression konversi idempoten.

## Dev Notes

- **Prinsip Master PRD §11.4:** *"AI tidak boleh menciptakan debt sebagai fakta tanpa evidence"* — konversi 22.1.4 selalu human-approved (16.3) dan wajib membawa `debt_source_ref` berisi scan/rec ref.
- **Struktur Master PRD §11:** debt registry adalah bagian dari AI Codebase Intelligence — karena itu UI-nya (22.2) hidup di tab eksisting AIIntelligenceView, BUKAN nav baru (menjaga kemenangan CC-4: 14 menu tidak bertambah).
- Aging dihitung server-side agar konsisten (jangan dihitung client); gunakan sumber waktu yang bisa di-inject di service untuk test deterministik.
- Owner = `assigneeId`, target milestone = `milestoneId`, effort = `estimateHours` — SEMUA sudah ada di work_items; JANGAN menambah kolom duplikat.
- Ikuti pola envelope + error + `safeAsync` + audit middleware eksisting di `work-item.routes.ts`; endpoint `/debts` read-only (tidak menambah write audit baru selain pola eksisting).
- Drizzle: tambahkan kolom via `pgTable` + file SQL migrasi manual mengikuti pola `0015_add_report_deliveries.sql` + update `server/db/migrations/meta`.
