# 12.1: Generated Reports Storage & Scheduling Endpoints

**Story ID:** 12.1
**Epic:** 12 — Scheduled Reporting Engine
**Slug:** generated-reports-storage
status: done

## Story

As a **Manager**,
I want **daily, weekly, and monthly reports generated on demand and archived as immutable history**,
so that **management reporting is consistent, auditable, and retrievable kapan pun**.

## Acceptance Criteria

<!-- LOCKED -->

1. Tabel `generated_reports`: `id`, `type` (DAILY|WEEKLY|MONTHLY), `periodFrom`, `periodTo`, `language` (id-ID), `contentMarkdown` (TEXT), `generatedAt`, `generatedBy` (userId) — via migrasi Drizzle, index `(type, generatedAt DESC)`.
2. `POST /api/v1/reports/generate` body `{ type }` (RBAC: PERM_AUDIT_LOGS_VIEW): DAILY = 1 hari kalender terakhir (kemarin), WEEKLY = 7 hari terakhir, MONTHLY = 30 hari terakhir; memanggil agregasi + generator 10.x, menyimpan arsip, mengembalikan objek laporan lengkap.
3. `GET /api/v1/reports/history?type=&limit=` (RBAC sama, default limit 20) mengembalikan arsip terbaru terurut `generatedAt DESC` dengan metadata (tanpa content penuh) + field `contentPreview` (200 karakter pertama).
4. `GET /api/v1/reports/history/:id` mengembalikan satu arsip utuh; id tidak ada → 404.
5. Arsip bersifat immutable: tidak ada endpoint update/delete; regenerasi membuat baris baru.

## Testing

- **Key scenarios:**
  1. POST `{type:"WEEKLY"}` → 201/200, arsip tersimpan dengan periodFrom = now-7d (toleransi < 5s), content memuat header laporan.
  2. type tidak valid → 400.
  3. History mengembalikan metadata + preview ≤ 200 char; detail by id utuh; id acak → 404.
