# 13.1: Incidents Schema, Declaration API & Status Lifecycle Machine

**Story ID:** 13.1
**Epic:** 13 — Incident Room & SLA Management
**Slug:** incident-schema-lifecycle
status: done

## Story

As a **Tech Lead (Incident Commander)**,
I want **a real incident backend: declare incidents, drive them through a validated status lifecycle, and read them back**,
so that **Incident Room operates on PostgreSQL truth instead of client mock data**.

## Acceptance Criteria

<!-- LOCKED -->

1. Tabel `incidents`: `id`, `code` (INC-NNNNN unik), `title`, `severity` (CRITICAL|MAJOR|MINOR), `environment` (Production|Staging), `serverName`, `impact`, `commanderUserId`, `commanderName`, `relatedTicketCode`, `runbookUrl`, `status`, `detectedAt`, `acknowledgedAt` (nullable), `resolvedAt` (nullable), `createdAt`, `updatedAt` — index pada `(status)`, `(severity)`, `code` unique.
2. `POST /api/v1/incidents` (PERM_INCIDENT_DECLARE): membuat insiden dengan status awal `INVESTIGATING`, code auto-generate `INC-NNNNN` berurutan unik, detectedAt default now (boleh di-supply), wajib title/severity/environment/impact.
3. `PATCH /api/v1/incidents/:id/status` (PERM_INCIDENT_COMMAND): transisi tervalidasi mesin status — `INVESTIGATING → IDENTIFIED → MONITORING → MITIGATED → RESOLVED`; transisi terlarang → 400 dengan kode error jelas; saat masuk `RESOLVED`, `resolvedAt` diisi server.
4. `GET /api/v1/incidents` (autentikasi + PERM_VIEW_DASHBOARD) mendukung filter `status`, `severity`, pagination `page`/`limit` (default 20), urut `detectedAt DESC`.
5. `GET /api/v1/incidents/:id` mengembalikan detail utuh; tidak ditemukan → 404.
6. Setiap deklarasi & transisi tercatat ke audit trail (`INCIDENT_DECLARED`, `INCIDENT_STATUS_CHANGED`) dengan correlation ID.
