# 1.4: Server-Side RBAC Enforcement & Frontend Sanitization

**Story ID:** 1.4  
**Epic:** 1 — Core Platform Foundation, Security & Database  
**Slug:** server-rbac-middleware  
status: done   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->  

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **Platform Admin / Security Lead**,  
I want **strict server-side RBAC middleware (`requirePermission`, `requireRole`) that cannot be fooled by client-forged token payloads, with all plaintext credentials and auto-admin bootstraps removed from the frontend**,  
so that **privilege escalation is impossible and client-side credentials are never exposed to public visitors (closing Deep Scan DS-02, DS-03, DS-05)**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Middleware server `requirePermission(...permissions)` dan `requireRole(...roles)` memeriksa hak akses pengguna dari satu matriks kebenaran di server:
   - Pengguna dengan permission yang sesuai diizinkan melanjutkan (`next()`).
   - Pengguna tanpa permission ditolak dengan `HTTP 403 Forbidden` menyertakan kode `RBAC_ACCESS_DENIED` dan daftar missing permissions.
2. Jalur pemalsuan token di `server.ts` (cabang yang menerima arbitrary base64 JSON payload dengan field `role`) dihapus total.
3. Seluruh array `DIRECTORY_USERS` dan petunjuk kata sandi (`passwordHint`) dihapus sepenuhnya dari file frontend `src/lib/auth.ts`, sehingga bundle browser publik bersih dari kredensial.
4. Metode `AuthManager.restoreSession()` di `src/lib/auth.ts` tidak lagi memanggil `bootstrapDefaultSession(DIRECTORY_USERS[0])`. Jika tidak ada sesi valid di `localStorage`, aplikasi tetap berada di state `UNAUTHENTICATED`.
5. Fallback login luring di `src/lib/auth.ts` yang menerima login sembarang email tanpa password saat server mati dihapus total.
