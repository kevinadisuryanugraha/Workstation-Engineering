# 8.3: AI Scanner Demo Mode Integrity Flag (SEC-05 / DS-10)

**Story ID:** 8.3
**Epic:** 8 — Security Hardening & Token Governance
**Slug:** ai-scanner-demo-integrity
status: done   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **Developer (pengguna AI Scanner)**,
I want **fallback scan results to be explicitly labeled as `STATIC_DEMO_PREVIEW` in both the API response and the UI**,
so that **I never mistake heuristic demo findings for real LLM code analysis**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Saat `GEMINI_API_KEY` tidak tersedia, response `POST /api/ai/scan` menyertakan field `mode: "STATIC_DEMO_PREVIEW"`; saat pemindaian LLM nyata berhasil, field berisi `mode: "LIVE_ANALYSIS"`.
2. UI komponen hasil scan menampilkan **banner/label peringatan visual yang mencolok** ketika `mode === "STATIC_DEMO_PREVIEW"` (mis. badge kuning "Data Demo — bukan hasil pemindaian nyata").
3. Field `mode` selalu ada pada response (tidak boleh `undefined`) agar klien tidak perlu menebak.
4. Perilaku pemindaian nyata (dengan API key) tidak berubah — hanya tambahan metadata integritas.

## Tasks / Subtasks

- [ ] API metadata mode (AC: #1, #3)
  - [ ] Temukan handler `/api/ai/scan`; tambahkan `mode` pada kedua jalur respons (fallback & live)
- [ ] UI warning (AC: #2)
  - [ ] Badge/banner kondisional pada komponen hasil scan berdasarkan `mode`
- [ ] Tulis Tests (AC: #1, #3)
  - [ ] `tests/ai-mode.test.ts` — tanpa API key → `mode: "STATIC_DEMO_PREVIEW"`; contract: field selalu ada
