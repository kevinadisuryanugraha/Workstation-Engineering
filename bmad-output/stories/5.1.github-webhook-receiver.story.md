# 5.1: GitHub Webhook Receiver with HMAC-SHA256 Verification & Idempotency

**Story ID:** 5.1  
**Epic:** 5 — Git Intelligence & Webhook Engine  
**Slug:** github-webhook-receiver  
status: done   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->  

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **Tech Lead / System**,  
I want **an asynchronous, idempotent GitHub webhook receiver endpoint that cryptographically verifies `X-Hub-Signature-256` and deduplicates delivery IDs**,  
so that **git activity (pushes, commits, PRs) is ingested securely and fast without timing out or creating duplicate records**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Endpoint `POST /api/v1/webhooks/github` menerima payload webhook GitHub mentah dan memvalidasi tanda tangan header `X-Hub-Signature-256` menggunakan HMAC-SHA256 dengan secret repositori terdaftar:
   - Request dengan signature tidak cocok ditolak dengan `HTTP 401 Unauthorized`.
2. Sistem mengecek header `X-GitHub-Delivery` terhadap tabel `webhook_deliveries`:
   - Jika delivery ID sudah ada dan pernah diproses, sistem segera mengembalikan `HTTP 200 OK` tanpa memproses ulang (idempotensi).
3. Payload baru disimpan ke tabel `webhook_deliveries` dengan status `PENDING`, dan endpoint segera mengembalikan response `HTTP 202 Accepted` dalam waktu < 50 ms.
4. Skema Drizzle `repositories` dan `webhook_deliveries` dibuat di PostgreSQL dengan constraint `UNIQUE` pada `webhook_deliveries.delivery_id`.
5. Error saat pemrosesan webhook dicatat ke server error log tanpa membocorkan secret webhook ke dalam log.

## Dev Notes

<!-- LOCKED. Concrete guidance compiled from planning docs with citations. -->

- **Requirements Citation:** FR-010 Registrasi Repository & Webhook Receiver GitHub. [Source: prd.md#FR-010]
- **ADR-005 Reference:** Asynchronous Idempotent GitHub Webhook Ingestion Engine. [Source: architecture.md#ADR-005]
- **Raw Body Handling:** Verifikasi HMAC membutuhkan *raw unparsed buffer* dari request body. Jangan gunakan `express.json()` standar yang sudah mem-parse body sebelum verifikasi signature dilakukan. [Source: architecture.md#ADR-005]
- **Latency Requirement:** Respons HTTP 202 wajib dikembalikan dalam < 50ms untuk mencegah timeout dari sisi pengirim GitHub. [Source: prd.md#NFR-001]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. -->

- **Approach:** Integration test dengan Supertest mengirimkan mock GitHub Webhook headers.
- **Key scenarios:**
  1. POST dengan signature salah mengembalikan HTTP 401 Unauthorized.
  2. POST dengan signature HMAC-SHA256 valid mengembalikan HTTP 202 Accepted.
  3. POST kedua dengan `X-GitHub-Delivery` yang sama mengembalikan HTTP 200 OK (Idempotent bypass).
