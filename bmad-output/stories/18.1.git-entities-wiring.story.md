# 18.1: Git Entities Wiring — Read Endpoint Server + Hydration Client

**Story ID:** 18.1
**Epic:** 18 — Client API Wiring: Honest Data Everywhere (Course Correction 5)
**Slug:** git-entities-wiring
status: ready-for-dev   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day. No story points.

## Story

As a **pengguna WORKSTATION di boot produksi**,
I want **tab Git Intelligence menampilkan commit & pull request nyata hasil ingest webhook**,
so that **bukti rekayasa (commits/PRs) yang tampil adalah kejadian nyata — bukan seed demo atau area kosong**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Server menyediakan read endpoint: `GET /api/v1/git/commits` dan `GET /api/v1/git/pull-requests` (JWT auth, JSON envelope ADR-004, filter opsional `projectId`, `limit` default wajar ±50, urut terbaru).
2. Client memakai hook React Query baru (`src/hooks/api/useGitEntities.ts`) dengan `enabled: !DEMO_MODE && isAuth` — mengikuti pola inline-query 17.2 (queryKey konsisten, tidak ada request 401 di login screen, tidak ada fetch percuma di mode demo).
3. Boot real: `GitIntelligenceView` menampilkan commits/PRs nyata dari API; honest-empty notice 17.3 otomatis tidak tampil saat data ada. Mode demo: seed mock + perilaku lama tidak berubah.
4. Mapping DTO→UI dilakukan di satu tempat (helper murni, testable) — field tanpa padanan API diisi placeholder jujur, bukan nilai palsu.
5. Tidak ada perubahan pada webhook receiver eksisting (idempotensi & HMAC tetap utuh); endpoint read bersifat tambahan (additive).
6. `npm run lint` (tsc strict) dan seluruh test tetap hijau; test baru untuk endpoint read + mapping.

## Dev Notes

- **Sumber masalah (CC-5):** Dev Agent Record 17.2 — Git Intelligence satu-satunya domain yang read endpoint-nya BELUM ada; datanya sudah terkumpul via webhook (Story 5.1/5.2) ke tabel `server/db/schema/commits.ts` & `pull_requests.ts`, hanya belum ada pembacanya.
- **Pola yang harus diikuti:** route module pattern `server/modules/git/git.routes.ts` (saat ini hanya `router.post('/github', ...)`; mount lama `/api/v1/webhooks`). Tambahkan handler list di file route yang sama atau file routes baru yang di-mount `app.use("/api/v1/git", authenticateToken, ...)` — ikuti gaya `deployment.routes.ts` + `safeAsync`/guard error yang ada.
- **Pola client 17.2:** inline `useQuery` di blok sumber data `App.tsx` dengan `enabled` gating; JANGAN memodifikasi hook lama yang tak punya opsi `enabled`. Mapper DTO→UI = pure function di dekat `mapProjectDto`/`mergeServerTelemetry`.
- **Perhatian:** UI `Commit`/`PullRequest` (src/types.ts) punya field tampilan (author avatar, linked item codes, dsb.) — isi dari kolom API yang ada; sisanya placeholder jujur ("—"). `linkedItemCodes` bisa diambil dari tabel evidence/links jika tersedia; jika tidak, kosong — JANGAN mengarang.
- **Terkait:** 17.2 (gating infra, done) · 18.2–18.6 (sibling stories).
