# 1.1: Git Repository Initialization & Quality Toolchain

**Story ID:** 1.1  
**Epic:** 1 — Core Platform Foundation, Security & Database  
**Slug:** git-init-and-toolchain  
status: done   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->  

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **Developer**,  
I want **the project managed in a clean Git repository with TypeScript strict mode enabled and an automated unit testing toolchain (Vitest)**,  
so that **code changes are tracked, regression is prevented, and our work is permanently protected from accidental loss (closing Deep Scan DS-07 & DS-11)**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Repositori Git lokal diinisialisasi (`git init`), branch utama dinamai `master` atau `main`, dan `.gitignore` memvalidasi pengecualian direktori `node_modules/`, `dist/`, `.env`, `.env.local` (hanya `.env.example` yang di-commit).
2. Konfigurasi `tsconfig.json` diaktifkan opsi `"strict": true`, dan kompilasi tipe lulus tanpa error saat dijalankan via `npm run lint` (`tsc --noEmit`).
3. Framework pengujian unit modern (**Vitest**) terpasang di devDependencies, dan skrip `npm run test` di `package.json` mengeksekusi suite tes dengan sukses (minimal 1 tes verifikasi environment berjalan hijau).
4. Metadata project di `package.json` diperbarui: mengganti nama boilerplate `"react-example"` menjadi `"workstation-engineering-intelligence"`, dengan versi awal `1.0.0-alpha`.
5. Komit Git awal (`Initial commit: WORKSTATION MVP foundation setup`) tersimpan bersih tanpa file sampah atau kredensial rahasia.

## Tasks / Subtasks

<!-- Every task maps to one or more ACs via (AC: #N). -->

- [ ] Inisialisasi Git dan audit file `.gitignore` (AC: #1, #5)
  - [ ] Jalankan `git init` di root project
  - [ ] Pastikan `.env*` dikecualikan kecuali `.env.example`
  - [ ] Pastikan `dist/` dan cache dikecualikan
- [ ] Aktifkan TypeScript Strict Mode (AC: #2)
  - [ ] Tambahkan `"strict": true` pada `compilerOptions` di `tsconfig.json`
  - [ ] Jalankan `npm run lint` dan perbaiki type error residual jika ada
- [ ] Pasang dan konfigurasi Vitest (AC: #3)
  - [ ] Pasang `vitest` sebagai devDependency
  - [ ] Buat file `vitest.config.ts` sederhana yang mendukung path alias `@/*`
  - [ ] Tambahkan skrip `"test": "vitest run"` pada `package.json`
  - [ ] Buat file tes sampel `tests/sanity.test.ts`
- [ ] Rapikan metadata `package.json` (AC: #4)
  - [ ] Ubah name dari `"react-example"` ke `"workstation-engineering-intelligence"`
  - [ ] Atur versi ke `"1.0.0-alpha"`
- [ ] Buat Initial Commit (AC: #5)
  - [ ] Review `git status` untuk memastikan tidak ada file rahasia
  - [ ] Buat komit pertama

## Dev Notes

<!-- LOCKED. Concrete guidance compiled from planning docs with citations. -->

- **Deep Scan Context:** Scan 18 Sep 2026 membuktikan direktori `.git` sama sekali tidak ada di working tree (DS-07) dan zero testing toolchain terpasang (DS-11). [Source: docs/DEEP-SCAN-REPORT-2026-09-18.md#DS-07]
- **TypeScript Configuration:** Di `tsconfig.json`, `allowImportingTsExtensions` saat ini aktif bersama `noEmit`. Pastikan `"strict": true` tidak merusak build Vite yang sudah ada. [Source: bmad-output/project-documentation.md#Section-2]
- **Testing Choice:** Vitest dipilih karena berjalan langsung di atas konfigurasi Vite eksisting tanpa perlu konfigurasi Babel/ts-jest yang rumit. [Source: architecture.md#8-technology-stack]
- **Security Check:** Jangan pernah memasukkan file `.env` yang berisi token API asli ke dalam komit Git! Gunakan `.env.example` sebagai template. [Source: prd.md#NFR-002]

## Testing

<!-- LOCKED. STRATEGY ONLY — what to verify and how. -->

- **Approach:** Verifikasi eksekusi CLI dan status file.
- **Key scenarios:**
  1. `git status` menunjukkan cabang aktif dan file ter-track bersih.
  2. `npm run lint` (`tsc --noEmit`) mengembalikan exit code 0 dengan `"strict": true`.
  3. `npm run test` menjalankan Vitest dan melaporkan 1 test suite passed.
- **Per-AC verification:**
  - AC #1: Periksa `ls -la .git` dan `git status`.
  - AC #2: Jalankan `npm run lint`.
  - AC #3: Jalankan `npm run test`.
  - AC #4: Baca isi `package.json`.
  - AC #5: Jalankan `git log -1`.
