# 21.1: Gemini Real Scan — Path Analisis Kode Nyata

**Story ID:** 21.1
**Epic:** 21 — Gemini Real AI Scan (Course Correction 6)
**Slug:** gemini-real-scan
status: done

## Story

As a **tech lead**,
I want **AI scan menganalisis kode proyek nyata via Gemini API saat kunci tersedia**,
so that **temuan & rekomendasi benar-benar berasal dari analisis LLM atas codebase — bukan hanya preview statis**.

## Acceptance Criteria

<!-- LOCKED -->

1. `ai.service.ts` memiliki path real: bila `GEMINI_API_KEY` tersedia (valid, non-placeholder), scan memanggil Gemini (`@google/genai`, model env `AI_SCAN_MODEL` default `gemini-2.5-flash`) dengan prompt terstruktur atas ringkasan repositori (pohon direktori terbatas + cuplikan file penting, maks ±40KB konteks) dan meminta respons JSON findings/rekomendasi sesuai skema eksisting.
2. Respons JSON diparse + divalidasi (field wajib, severity enum, confidence 0-1); entri tidak valid dibuang dengan log — scan tetap sukses bila ≥1 entri valid.
3. Scan tersimpan dengan mode BARU `REAL_GEMINI` (ditambahkan ke `AI_SCAN_MODES` — migrasi TIDAK diperlukan karena kolom varchar, hanya enum TS) dan `model` berisi nama model aktual.
4. Tanpa kunci / error API / parse gagal total → fallback `buildStaticDemoPreview()` eksisting dengan mode `STATIC_DEMO_PREVIEW` — perilaku lama utuh, TIDAK ada crash, dan hasil tetap jujur terlabel demo.
5. Setiap path (real & fallback) tetap tersimpan di `ai_scans` + audit-logged (pola eksisting 16.1).
6. `npm run lint` + seluruh test hijau; test baru: real path dengan client Gemini palsu (injectable), validasi/parse JSON, fallback tanpa kunci, label mode benar.
