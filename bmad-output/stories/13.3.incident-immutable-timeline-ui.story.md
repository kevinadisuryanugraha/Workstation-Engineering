# 13.3: Append-Only Incident Events Timeline & Incident Room Live Wiring

**Story ID:** 13.3
**Epic:** 13 — Incident Room & SLA Management
**Slug:** incident-immutable-timeline-ui
status: done

## Story

As a **Incident Commander & Manager**,
I want **every incident event recorded on an immutable timeline and the Incident Room UI reading live API data with SLA badges**,
so that **the incident narrative is forensically trustworthy and visible in real time**.

## Acceptance Criteria

<!-- LOCKED -->

1. Tabel `incident_events` append-only: `id`, `incidentId` (FK), `type` (alert|action|mitigation|resolution|note), `message`, `actorName`, `actorUserId`, `correlationId`, `createdAt` — index `(incidentId, createdAt)`; TIDAK ada endpoint update/delete (append-only, pola ADR-007).
2. Event otomatis tercatat: deklarasi (alert), tiap transisi status (type mengikuti: IDENTIFIED/MONITORING→action, MITIGATED→mitigation, RESOLVED→resolution), plus `POST /api/v1/incidents/:id/events` untuk menambah note manual (autentikasi + PERM_VIEW_DASHBOARD).
3. `GET /api/v1/incidents/:id/events` mengembalikan timeline kronologis menaik (`createdAt ASC`).
4. Hook `src/hooks/api/useIncidents.ts` (React Query) mengambil daftar + detail + events; `App.tsx` memetakan API → tipe `Incident` UI (code, severity, timeline {time, event, actor, type}, sla badge data) menggantikan `mockIncidents` saat sesi aktif.
5. Badge SLA tampil di kartu insiden: hijau (MET), merah (BREACHED/overdue), abu (PENDING) — berdasarkan objek `sla` dari 13.2.

## Dev Notes

- **Requirements Citation:** Master PRD §30 — timeline insiden immutable. [Source: docs/WORKSTATION_Super_Duper_PRD.pdf#30]
- **Immutable:** tanpa UPDATE/DELETE di seluruh jalur kode event (mirip audit_logs). [Source: architecture.md#ADR-007]
- **UI contract:** `Incident.timeline: { time, event, actor, type? }[]` — mapping dari createdAt/message/actorName/type. IncidentRoomView existing tetap dipakai; data diganti live. [Source: src/types.ts#209, src/components/IncidentRoomView.tsx]
- **Konsistensi mutasi:** transisi status di 13.1 kini juga menulis event — refactor di service layer, kontrak API 13.1 tidak berubah. [Source: stories/13.1]

## Testing

- **Key scenarios:**
  1. Declare → 1 event alert; transisi penuh → events berturut dengan type benar; urutan ASC.
  2. Endpoint note menambah event; endpoint update/delete TIDAK ada (404 pada method tak dikenal).
  3. Mapper UI: API → Incident (timeline & sla badge mapping benar; MET→hijau, BREACHED→merah, PENDING→abu).
  4. Events milik insiden lain tidak bocor (filter incidentId).
