# 4.2: Bi-directional Linking: Ticket ↔ Work Item & Evidence Engine

**Story ID:** 4.2  
**Epic:** 4 — Ticketing & ITSM Issue Resolution  
**Slug:** ticket-work-item-linking  
status: done   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->  

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **Developer / Support Engineer**,  
I want **a mechanism to link tickets directly to work items (or create a new task directly from a ticket) and verify the resolution link**,  
so that **a reported problem has clear traceability to the engineering task solving it and cannot be marked `RESOLVED` without an evidence trail**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Skema Drizzle `evidence_links` dibuat di PostgreSQL dengan field: `id`, `ticket_id` (FK ke `tickets`), `work_item_id` (FK ke `work_items`), `commit_id`, `pr_id`, `deployment_id`, `created_at`.
2. Endpoint `POST /api/v1/tickets/:id/link-work-item` mengaitkan tiket ke work item yang sudah ada, atau membuat work item baru bertipe `BUG` dan menautkannya secara otomatis.
3. Pada respons detail tiket (`GET /api/v1/tickets/:id`), field `linkedWorkItems` dan `evidence` menampilkan data work item terkait beserta statusnya.
4. Pada respons detail work item (`GET /api/v1/work-items/:id`), field `linkedTickets` menampilkan seluruh tiket yang dipecahkan oleh tugas tersebut.
5. Saat tiket hendak dipindahkan ke status `RESOLVED` via `PATCH /api/v1/tickets/:id/status`, sistem memverifikasi bahwa minimal ada 1 tautan work item berstatus `DONE` ATAU minimal 1 commit SHA bukti ATAU alasan resolusi manual (*resolution notes*) yang jelas.
