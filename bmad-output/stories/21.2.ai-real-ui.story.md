# 21.2: AI Real UI — Badge Mode & Filter Riwayat Scan

**Story ID:** 21.2
**Epic:** 21 — Gemini Real AI Scan (Course Correction 6)
**Slug:** ai-real-ui
status: ready-for-dev

## Story

As a **pengguna panel AI**,
I want **melihat dengan jelas apakah hasil scan berasal dari Gemini nyata (REAL_GEMINI) atau demo statis**,
so that **saya tidak pernah salah menganggap preview demo sebagai analisis sungguhan** (prinsip integritas SEC-05/16.1).

## Acceptance Criteria

<!-- LOCKED -->

1. Kartu hasil scan & daftar riwayat menampilkan badge mode: `REAL_GEMINI` (badge aksen positif, label "Gemini Real") vs `STATIC_DEMO_PREVIEW` (badge peringatan, label "Demo Statis") — tiga nilai mode lama (bila ada) tetap ter-handle tanpa crash (guard switching, pelajaran HOTFIX #4).
2. Riwayat scan memiliki filter mode (Semua / Real / Demo) yang diteruskan sebagai query param ke endpoint eksisting (server 16.1 sudah mendukung filter bila ada; bila belum, filter dilakukan client-side atas data termuat — pilih yang benar sesuai kode aktual, jangan ubah kontrak endpoint tanpa perlu).
3. Model aktual (`model`) ditampilkan pada detail hasil (mis. "gemini-2.5-flash").
4. Mode demo (VITE_DEMO_MODE) mempertahankan perilaku mock eksisting — badge tetap jujur.
5. Tidak ada crash saat daftar kosong/hydration belum selesai (loading skeleton / empty state jujur).
6. `npm run lint` + seluruh test hijau; test baru: pemetaan badge per mode, filter, guard mode tak dikenal.
